= Marid Roadmap & Issue Breakdown
:toc:
:sectnums:

[abstract]
The Marid execution roadmap and reviewable issue breakdown (`PROJECT_BRIEF.md` §9;
`docs/MARID-FRAMEWORK.adoc`). Translates the framework gates and charter phases into
independently verifiable work units with explicit acceptance tests.

== The Six Program Gates

[cols="1,1,2,2",options="header"]
|===
| Gate | Phase Coverage | Objective | Deliverables & Evidence

| **Gate 0**
| Phase 0 + All Feasibility
| Feasibility and licensing discovery; eliminate unknown risks before implementation.
| `feasibility.adoc`, `licensing.adoc`, reconciled architecture and compatibility specs, ADRs.

| **Gate 1**
| Entry to Phases 1–3
| Prove high-risk integration assumptions using disposable minimal spikes.
| Disposable spikes: ArangoDB HTTP wire client, GraphQL SDL parsing, Bebop serialization check.

| **Gate 2**
| Setup for Phases 1–2
| Foundation, skeletons, toolchain pins, and shared contracts.
| Julia LTS/Current CI matrix, Bun & AffineScript pins, `Project.toml` manifests, `CallContext` contract.

| **Gate 3**
| Phases 1–3 (Core & Storage)
| Implement independent Julia integration packages.
| `MaridIR`, `MaridCodec`, `MaridOpenAPI`, `MaridRPC`, `MaridGraphQL`, `MaridTransport`, `MaridCore`, `ArangoDB`, `MaridStorage`.

| **Gate 4**
| Assembly & Phase 5 (Frontend)
| Browser clients, framework integrations, and the canonical reference application.
| `@metadatastician/marid-client`, `@metadatastician/marid-react`, `@metadatastician/marid-vue`, `@metadatastician/marid-elements`, `relationship_explorer` reference app.

| **Gate 5**
| Release Review (Full Program)
| Final quality, performance, and security audit; release readiness.
| Full test pass, zero skipped tests, SonarQube green gate, verified reproducible installation.
|===

== Reviewable Issue Breakdown

=== Issue MARID-001: Gate 1 — Disposable ArangoDB HTTP Wire Spike
* **Goal**: Prove that pure Julia (`HTTP.jl` + `JSON3.jl`) can communicate with an ArangoDB 3.12 container, create a collection, insert a document, and execute an AQL cursor query with cursor cleanup.
* **Scope**: Standalone test script without `MaridCore` dependencies.
* **Non-Goals**: Full error mapping, connection pooling, multi-statement transactions.
* **Dependencies**: Docker/Podman running `arangodb:3.12`.
* **Acceptance Tests**:
  - Script connects to `http://localhost:8529/_api/version` and verifies version `3.12.*`.
  - Script executes an AQL query via `POST /_api/cursor` and fetches all results using cursor iteration.
  - Script deletes the cursor explicitly via `DELETE /_api/cursor/{id}`.
* **Files Affected**: `test/spikes/arango_spike.jl`.
* **Blockers**: None.

=== Issue MARID-002: Gate 1 — Disposable GraphQL SDL Introspection Spike
* **Goal**: Validate that `GraphQLite.jl` can parse and validate an emitted GraphQL SDL schema text and execute an introspection query against it.
* **Scope**: Single-file spike testing schema generation and AST validation.
* **Non-Goals**: Full runtime resolver pipelines or subscription streaming.
* **Dependencies**: `GraphQLite.jl`.
* **Acceptance Tests**:
  - Validates that generated SDL containing custom types, queries, and mutations passes validation without syntax errors.
  - Executes a standard `__schema` introspection query and receives a valid JSON structure.
* **Files Affected**: `test/spikes/graphql_spike.jl`.
* **Blockers**: None.

=== Issue MARID-003: Gate 2 — Monorepo Skeletons & Toolchain Pinning
* **Goal**: Establish independent `Project.toml` files for all Phase 1–3 packages, configure CI matrices for Julia 1.10 LTS and 1.11 Current, and wire DCO and dependency-review checks.
* **Scope**: Package manifests, CI workflows, and toolchain configurations.
* **Non-Goals**: Functional implementation of package APIs.
* **Dependencies**: Julia 1.10, Julia 1.11, Bun 1.1.
* **Acceptance Tests**:
  - `just validate` passes without errors.
  - GitHub Actions runs `Project.toml` validation across all 9 initial packages.
* **Files Affected**: `packages/*/Project.toml`, `.github/workflows/julia-ci.yml`, `.github/workflows/dco.yml`.
* **Blockers**: None.

=== Issue MARID-004: Gate 2 — CallContext & Streaming Seam Contracts
* **Goal**: Formalize `CallContext`, `MaridError`, and the streaming handler abstraction `Stream{I} -> Stream{O}` in `MaridCore`.
* **Scope**: Core contracts, immutable structs, cancellation event propagation, and domain error hierarchies.
* **Non-Goals**: Protocol-specific encoders or HTTP server binding.
* **Dependencies**: Standard Julia `Base` and `Dates`.
* **Acceptance Tests**:
  - Unit tests prove `CallContext` is immutable and carries deadlines and cancellation signals.
  - Cancellation signal cancels downstream worker channels within < 10ms.
* **Files Affected**: `packages/MaridCore/src/context.jl`, `packages/MaridCore/src/errors.jl`.
* **Blockers**: None.

=== Issue MARID-005: Gate 3 — MaridIR Service Descriptors
* **Goal**: Implement `MaridIR.jl` as the single source of truth for services, RPC methods, fields, and streaming signatures.
* **Scope**: Pure data structs, validation logic, and immutability invariants.
* **Non-Goals**: Code generation (handled by emitters).
* **Dependencies**: None (zero external dependencies).
* **Acceptance Tests**:
  - Constructing valid service descriptors passes validation.
  - Malformed descriptors (duplicate endpoints, missing types) throw descriptive errors.
  - 100% test coverage with zero allocations on descriptor reading.
* **Files Affected**: `packages/MaridIR/src/*`, `packages/MaridIR/test/*`.
* **Blockers**: None.

=== Issue MARID-006: Gate 3 — ArangoDB Standalone HTTP Client
* **Goal**: Implement `ArangoDB.jl` supporting documents, edges, bound AQL queries, cursors, and revision-aware updates.
* **Scope**: Native Julia HTTP client talking directly to ArangoDB REST API.
* **Non-Goals**: Relational ORM mapping; clustering Agency management.
* **Dependencies**: `HTTP.jl`, `JSON3.jl`.
* **Acceptance Tests**:
  - Integration tests against ArangoDB 3.12 container.
  - Cursor pagination, batch size limits, and explicit cleanup tested.
  - Conflict detection (`ERROR_ARANGO_CONFLICT`) verified on concurrent updates.
* **Files Affected**: `packages/ArangoDB/src/*`, `packages/ArangoDB/test/*`.
* **Blockers**: None.

=== Issue MARID-007: Gate 4 — Reference Application: Relationship Explorer
* **Goal**: Deliver the end-to-end reference application backed by ArangoDB and `Cladistics.jl`, exposing services over HTTP/JSON and GraphQL.
* **Scope**: Full application exercising entity creation, edge connections, neighborhood traversal, and phylogenetic tree reconstruction with progress updates.
* **Non-Goals**: Full commercial UI; plain JS, React, and Vue reference frontends.
* **Dependencies**: `MaridCore`, `ArangoDB`, `MaridGraphQL`, `MaridTransport`, `Cladistics.jl`.
* **Acceptance Tests**:
  - Entities and edges persisted in ArangoDB.
  - Long-running Fitch parsimony analysis executes in background Julia task with progress pushed via SSE.
  - Frontends display live graph neighborhood and tree updates.
* **Files Affected**: `examples/relationship_explorer/*`, `test/interop/*`.
* **Blockers**: None.
