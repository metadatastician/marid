== How to run one

. Paste the file's content as the *first* message of a new chat.
. The agent must produce an evidence-first report before code: read the named
   files, run the named commands, and state what it saw.
. Every plan ends with an explicit *stop* condition. Honour it: several of these
   touch published artefacts, signatures, or another repository's `main`.
. Nothing here authorises a push to another repository's default branch, a
   package registration, a release, or a deployment. Those stay owner actions.

== Ground rules shared by every plan

* Doctrine: holes before features; fixes first on firm foundations; fail loudly,
   seal soundly; report faithfully — no overclaim; wire first; solutions at
   source (fix the canonical origin, not the downstream symptom); elegance by
   default with departures labelled; stop-first for outward-facing actions.
* Never equate a mock, a shim, a skipped test or a unit suite with
   interoperability.
* If a toolchain is missing, say so and fail closed. Never fabricate a result,
   a version pin, or an assertion count.
* Commits carry DCO sign-off and are signed by the owner's key. If you cannot
   sign, say so in the report and let the owner re-sign; do not silently produce
   unsigned commits on a protected branch.
