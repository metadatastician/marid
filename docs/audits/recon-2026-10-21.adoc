== Executive summary

The *program* has improved markedly since September: JSON3 replaced string
encoding, q-value negotiation is real and tested, a bounded HTTP/1.1 listener
exists with lifecycle flags, the capability-spec emitter and CLI are the most
carefully engineered code in the repository, and hosted Julia CI is green. The
*repository's self-description* has not kept up, and three things are now true
that were not true in September:

. **The agent-facing truth is false and can no longer be regenerated.**
   `CLAUDE.md` tells every arriving agent the project is “phase maintenance;
   maturity production; 100% complete”. `README.adoc`, the evidence ledger and
   `marid_chora.deed` say incubating/experimental with no accepted release
   gate. The generator that produced that line requires five `.a2ml` files that
   no longer exist, and the drift check that is supposed to catch this only
   tests that the file exists. (C02)
. **The golden path does not run.** `just test` shells a Python loop naming a
   package `ArangoDB` that has been `MaridArango` for weeks, so the recipe can
   never pass; and `just quality` is `fmt-check lint test` where the first two
   are still template `@echo` stubs. The documented gate
   (`just test && just quality`) is therefore satisfied by doing nothing. (C01,
   A03)
. **Six hosted gates are red for one reason that is not in this repository.**
   Governance, Hypatia, Secret Scanner, SonarQube and Rust CI all fail at *Set
   up job* with “Unable to resolve action `actions/checkout@3d3c42e5…`: invalid
   lockfile pin”; they are exactly the workflows that call
   `hyperpolymath/standards/...reusable.yml@da2c748`. (C18, A06)

Beyond self-description, the substantive defects are concentrated where the
code is least exercised: `MaridArango` (an in-memory mock with no HTTP at all,
whose AQL “cursor” returns every document in every collection),
`MaridStorage` (a silently harmless “Arango” adapter), `MaridOpenAPI`
(un-escaped hand-built JSON), `MaridGraphQL` (SDL that cannot validate),
`MaridRPC` (leaks exception text), `MaridRaft` (a log-truncation rule that is
unsafe under Raft), and `MaridControl` (`swap_snapshot!` still uncallable, a
blocking `put!` under a lock). The reference application does not run on the
only server implementation that exists.

For the maintenance question in the request — corrective vs adaptive vs
perfective — the single most consequential *adaptive* finding is that
**HTTP.jl 2.x (a Reseau-backed rewrite published 2026-05-28, now 2.11.1) has
superseded the 1.x line Marid is pinned to, and Marid's listener reaches into
1.x internals that 2.x explicitly no longer supports.** That migration is also
what unlocks SSE, WebSocket and HTTP/2 — three things the charter needs anyway.

== Corrective findings — broken now

=== C01 — `just test` cannot pass, and cannot fail (P0, *fixed in this change*)

*Evidence.* `scripts/marid:284` lists `'ArangoDB'`; the directory is
`packages/MaridArango` (`MaridTransport` CI matrix and `julia-ci.yml` both use
the correct name). With a stub `julia` that exits 0, the same command prints
“All 13 packages passed!” — including for the nonexistent directory — so the
harness measures process status, not test execution. It also runs without
`--startup-file=no` and without `scripts/bootstrap.jl`, while CI does both, so
a local green is not the CI green.

*Impact.* The ANCHOR golden path is `just test && just quality`; the first half
fails on any real Julia, the second half cannot fail (A03). Both halves of the
documented gate are broken, in opposite directions.

*Disposition.* Replaced with a bash loop that (a) refuses to run without
`julia`, (b) requires every package directory to exist, (c) bootstraps each
package exactly as CI does, and (d) verifies each suite's exit status
individually. Verified in this session with stub `julia` binaries for both the
all-pass and one-fail paths.

=== C02 — the arrival pack asserts a maturity that no source supports (P0)

*Evidence.* `CLAUDE.md:69`: “phase maintenance; maturity production; 100%
complete; status active”. `README.adoc:31`: “release gates are not accepted”.
`docs/audits/evidence-ledger.adoc:8`: “CLADE's `incubating` phase remains
authoritative”. `.machine_readable/descriptiles/marid_chora.deed`:
`:phase incubating`, `:version "0.1.0"`. The generator
(`.machine_readable/arrival-pack/generate.sh`) reads
`extract.sh`, which hard-requires `descriptiles/{CLADE,ECOSYSTEM,AGENTIC,STATE}.a2ml`
and `descriptiles/anchors/ANCHOR.a2ml`; none of the five exist (the tree kept a
`.deed` and an `anchors/README.adoc`). So `just claude-md` exits 2 and the
committed text cannot be regenerated or verified. `arrival-pack/verify.sh` —
what `just validate-claude-md` runs — only checks that `CLAUDE.md` exists.

*Impact.* This is the highest-harm defect in the repository: doctrine §9 (wire
first), §10 (report faithfully), the AFFIRMATION ethos, and the whole reason
`CLAUDE.md` exists, all fail in the file a new agent is told to read before
anything else. A model that trusts it will assume a completed production
framework and act accordingly.

*Disposition.* Not hand-edited here (the region is declared generated, and
hand-editing it is itself a flagged error). Recommended fix, in order:
(1) make `extract.sh` read `marid_chora.deed` for identity/phase (it already
carries `:phase`, `:repo-uuid`, `:languages`, `:license`) and *fail loudly* for
the fields the deed does not declare rather than defaulting them;
(2) make `verify.sh` re-render and byte-compare whatever it can, and exit 1
with “cannot verify: missing inputs” when it cannot — never “OK: present”;
(3) regenerate. That will flip `just validate-claude-md` to red until (1) lands,
which is the honest state.

=== C03 — `swap_snapshot!` is still uncallable (P0)

*Evidence.* `packages/MaridControl/src/MaridControl.jl:46`:
`function swap_snapshot!(cfg::AtomicConfig, next::Snapshot)::Snapshot` whose body
is `@atomicreplace cfg.current cfg.current => next`, which returns
`(old = ::Snapshot, success = ::Bool)` in Julia 1.7+. The return annotation
therefore throws on every call. (The September recon reproduced this; nothing
has changed and no test calls the function — `packages/MaridControl/test/runtests.jl`
tests `update_snapshot!` only.)

*Disposition.* Decide the contract, then test it: either
`swap_snapshot!` returns `Bool`/the previous `Snapshot` (CAS semantics:
`@atomicreplace` gives you `success`, which is the useful signal), or it returns
a named tuple and is documented as such. Add the missing test either way.

=== C04 — `MaridArango` is an in-memory mock claiming to be an HTTP client (P0)

*Evidence.* `packages/MaridArango/src/MaridArango.jl` contains no HTTP call,
no socket, and no URL construction — `using Sockets` at :15 is never used and
the `endpoint`/`timeout_secs` fields of `ArangoClient` are never read. Every
operation reads or writes the process-global `MOCK_STORAGE` (:70). Specifically:

* `create_cursor` ignores `query.aql` and `query.bind_vars` entirely and returns
  *every document in every collection of the database* (:135–160). Any AQL
  filter silently returns unfiltered data.
* `begin_transaction`/`commit_transaction`/`abort_transaction` return a
  synthetic `tx_<ns>` string and `true` (:240–250) — “abort” cannot abort.
* `_key` defaults to `string(length(collection) + 1)` (:92), which reissues a
  deleted key.
* `next_batch` hardcodes a batch size of 100 (:180), ignoring `query.batch_size`.
* `MOCK_STORAGE` is global and never reset, so test order changes results.

*Disposition.* Two honest options, in the spirit of the plan's E1: rename to
explicit test doubles (`MaridArango.Mock`) and make the real client a separate,
disabled seam, or implement the HTTP client (HTTP.jl 2.x already gives you
client pooling, retries, timeouts). Do not leave a module docstring that says
“Standalone native Julia HTTP client for ArangoDB 3.12” over code that never
opens a socket.

=== C05 — `ArangoStorageEngine` silently delegates to memory (P0)

*Evidence.* `packages/MaridStorage/src/MaridStorage.jl:56–76`: every CRUD
method forwards to `engine.in_memory_fallback`; `endpoint` and `database` are
never used. The suite named “ArangoStorageEngine Seam”
(`packages/MaridStorage/test/runtests.jl:33`) therefore asserts that the memory
dictionary works.

*Impact.* A caller configures an endpoint, gets successful writes, restarts,
and loses data with no warning — exactly the failure mode the recovery plan's
E1 forbids (“Never silently fall back to ephemeral memory when the DB is
unavailable”).

*Disposition.* Either construct it only as an explicit test double (named so),
or throw on first use with a message naming the unimplemented operation.
`get_entity` also returns the internal dictionary by reference (P14).

=== C06 — JSON-RPC leaks internal exception text (P0, security)

*Evidence.* `packages/MaridRPC/src/MaridRPC.jl:39`:
`Dict("code" => -32603, "message" => "Internal error: $(sprint(showerror, e))")`.
The HTTP slice was carefully changed to redact 500s
(`MaridCore/ext/MaridHTTPJSONExt.jl:78`: “Never serialize exception messages,
stacks or input payloads for 500s”); the RPC package does the opposite.
Additionally: no notification handling (a request without `id` must produce no
response), no batch support, `-32602` is never used, and
`RpcResponse.result::Union{Dict,Nothing}` cannot carry a scalar or an array.

*Disposition.* Return `-32603` with a fixed string, log the detail server-side
keyed by the request id; widen `result` to `Any`/`Union{...,Nothing}`; add the
notification and batch cases to the suite (they are pure functions, so this is
cheap and needs no transport).

=== C07 — OpenAPI emitter produces invalid JSON and invalid OpenAPI (P1)

*Evidence.* `packages/MaridOpenAPI/src/MaridOpenAPI.jl:21–40` builds the
document by string interpolation. A description containing `"` or a newline
yields invalid JSON; two methods sharing a path emit two `"path"` keys (last
wins for most parsers, but the document is malformed); there is no
`components.schemas`, no `requestBody`, no `parameters` for `:id`, and no
Error/4xx responses. The test only greps for four substrings.

*Disposition.* Emit through JSON3 (`MaridOpenAPI` may take a JSON dependency;
JSON3 is already in the family), build a `Dict` and serialise once, group
methods by path, convert `:param` to `{param}` in path templates, and add a
negative golden test with a quote/newline/emoji in the description. Validate
the result with an independent OpenAPI validator in CI (spectral or
`openapi-spec-validator`) — the brief requires exactly that (“Emitted specs
validate with independent tooling”).

=== C08 — GraphQL SDL cannot validate, and introspection is a substring match (P1)

*Evidence.* `packages/MaridGraphQL/src/MaridGraphQL.jl`: `_type_name` maps
`Void`, `Bytes`, `UInt32`, `UInt64` to `String` (:19–33) — undefined or lossy;
`emit_graphql_sdl` emits `type Query` only if some method uses GET (:57), so a
mutation-only service emits a schema GraphQL rejects (a schema must have a query
type); object-typed inputs are emitted as single `input:` arguments with no
`input` types declared; field names and descriptions are not escaped.
`execute_graphql_query` (:78) is `occursin("__schema", query_str)` and returns
`types` as a list of strings, which is not the spec's `__Type` shape.

*Disposition.* Emit a minimal valid schema always (`type Query { _empty: Boolean }`
when nothing else), map `Void` to a real scalar or omit it, and either implement
introspection from a parsed query (adopting a maintained parser is the plan's
F1) or stop calling it introspection.

=== C09 — live helpers build JSON/HTML by interpolation (P1, injection-adjacent)

*Evidence.* `packages/MaridLive/src/MaridLive.jl`: `hx_trigger_header` (:36)
joins `"\"$k\": \"$v\""` — a value containing `"` or a newline produces a
malformed `HX-Trigger` header, and a CRLF would be a response-splitting attempt
if nothing downstream rejects it; `datastar_merge_signals` (:100) does the same
and renders non-strings with Julia syntax (`[:a, :b]`, `Dict(...)`), which is
not JSON; `turbo_stream` (:72) and `hx_swap_oob` (:22) interpolate `target`/
`target_id` into an attribute without escaping.

*Disposition.* One JSON encoder for the family (JSON3 for anything server-side;
a small `escape_attribute` for HTML attributes), reject CR/LF in header values,
and add tests with quotes, newlines and `<script>` in the values.

=== C10 — readiness is a flag nobody reads; problem-details URIs are wrong (P1)

*Evidence.* `is_ready` is written in `MaridHTTPJSONExt.jl:87–88` and read only
by tests and `examples/http_json/server.jl`; the request path checks
`app.is_draining` only (:22). A process that has never become ready, or that
failed to bind, still answers 200 on application routes. `errors.jl:68–72` builds
`type` and `instance` as `"https://marid.hyperpolymath.org/errors/$(typeof(err))"`
and `"/errors/$(typeof(err))"`, i.e. `MaridCore.NotFoundError` — not a stable
URI and not RFC 9457's “type identifies the problem kind”.

*Disposition.* Check `is_ready` (and answer 503 during startup) before routing;
give each error struct a `const` slug (`"not-found"`, `"validation"`, …) and use
it in `type`/`instance`; keep `title` human-readable.

=== C11 — control-plane concurrency and honesty (P1)

*Evidence.* `packages/MaridControl/src/MaridControl.jl:118–124`: `put_key!`
holds `backend.lock` while calling `put!` on each subscriber channel, which for
a capacity-0 `Channel` blocks until a receiver arrives — a deadlock whenever a
subscriber exists and is not already parked (there is no `subscribe` API, so the
only way to add one is to push onto the public vector). `sync_from_backend!`
(:150) takes a `Dict` of updates and merges it without consulting
`node.backend` or `is_connected`; its docstring promises the opposite.

*Disposition.* Use buffered channels with an explicit drop policy (and document
it), push outside the lock, add a supported `subscribe`/`unsubscribe`; make
`sync_from_backend!` either read the backend or stop claiming to.

=== C12 — transport internals, unread bodies, and swallowed interrupts (P1)

*Evidence.* `packages/MaridTransport/src/http.jl`:

* `listening_port` (:10) reads `server.listener.server` — undocumented HTTP.jl
  1.x internals. HTTP.jl 2.0's release notes say undocumented 1.x internals
  “are no longer supported migration targets”, so this is already a migration
  blocker (A01), not merely fragile.
* `_read_request` returns a 400/413 `TransportResponse` without consuming the
  remaining request body (:27–40); whether the connection is then closed or
  reused determines whether a keep-alive client can desynchronise. The example
  suite sends a chunked 413 and then closes the socket, so it does not answer
  this. Needs an explicit two-request-on-one-connection test.
* The handler wrapper is a bare `catch` (:76), which also swallows
  `InterruptException` — a Ctrl-C during a request becomes a 500 response.
* `HTTP.setheader(stream,"Content-Length" => …)` is set after copying handler
  headers, so a handler that sets its own length emits two.

*Disposition.* Migrate `listening_port` to a supported API (or return the port
from `serve_http`, which is where it is known); catch `Exception` and rethrow
`InterruptException`; add the keep-alive test; de-duplicate headers.

=== C13 — Raft: unsafe truncation, broken commit propagation, phantom export (P0 *if* used)

*Evidence.* `packages/MaridRaft/src/MaridRaft.jl`:

* :155–162 — on a `prev_log_term` mismatch the follower does
  `resize!(node.log, args.prev_log_index - 1)`. Raft never truncates on a
  heartbeat mismatch; it replies false and lets the leader decrement
  `nextIndex`. As written, a leader with a shorter log can delete committed
  entries from a follower.
* :204–215 — the commit index only advances inside an AppendEntries whose
  *prev index matches*. The leader's commit-notification pass (:262) reuses
  `prev_log_index = new_idx`, so a follower that missed the entry also misses
  the commit, and nothing retries; `reply.success == false` is ignored.
* :222 — commits without checking `entry.term == current_term` (the §5.4.2
  rule), so a leader can commit a previous term's entry by counting replicas.
* :25 — `export … step_clock!` where no `step_clock!` exists anywhere
  (`UndefVarError` on use), while the module docstring advertises “randomized
  election timeouts”.
* No durable `current_term`/`voted_for` (Raft requires they survive restarts).

*Disposition.* This package is already marked experimental and out of default
assembly; keep it that way, and either fix the truncation/commit rules first or
delete the module rather than ship a consensus implementation that can violate
safety. The cheap, correct fix for the export is to remove it.

=== C15 — the reference application cannot run on the only server (P1)

*Evidence.* `examples/relationship_explorer/src/server.jl` registers routes
that return a stream of N items for `GET /api/v1/taxa` (:22–34) and, for
`POST /api/v1/analysis`, return an open stream and fill it from a detached
`@async` task (:44–70). `serve_json` requires “exactly one item in a closed
stream before returning” (`MaridHTTPJSONExt.jl:47–52`), so every one of these
routes fails; and the background task can push into a stream the transport has
already closed, raising inside an unmonitored task. The binary export routes
return the literal strings `BOP001_TAXA_STREAM_PAYLOAD` and
`CAPNP001_SEGMENT_STREAM_PAYLOAD` (:80, :95) presented as encoded payloads.
The app also builds its routes by hand while a separate `service_descriptor()`
describes the same API — the IR-first commitment is violated by construction,
and the two can drift silently.

*Disposition.* Pick the contract (unary JSON now, streaming later behind a
transport that supports it), bind routes with `bind_service!` from the one
descriptor, use `errormonitor(@async …)`, and delete the fake payload routes
until real fixtures exist.

=== C16 — the generator CLI converts failures into empty artefacts (P1)

*Evidence.* `scripts/marid` `generate` path: `resolve_service` `@warn`s on
include/eval failure and returns
`ServiceDescriptor(basename, "1.0.0", [], [])`; the command then prints an
empty-but-well-formed `.proto`/schema and exits 0. Worse, it searches for a

=== C20 — browser client: reconnection, retries, and SSE parsing (P1)

=== A01 — HTTP.jl 2.x supersedes the pinned 1.x line (P0 for the roadmap)

[cols="1,3",options="header"]
|===
| Fact | Detail

| HTTP.jl v2.0.0 released
| 2026-05-28; current release v2.11.1 (2026-10-21, i.e. today)

| Nature of the change
| “a breaking major release and a broad rewrite of the package internals and
  public API on top of Reseau.jl”

| Consequences that land on Marid
| `Response.status_code` → `Response.status`; the client layer stack / `pool` /
  `sslconfig` / `retry_*` APIs are gone (replaced by `HTTP.Client`,
  `HTTP.Transport`, `retry_if`, `request_timeout`); WebSockets moved under

  migration targets”

| What Marid pins
| `HTTP = "1.10"` in `packages/MaridTransport/Project.toml` and
  `examples/http_json/Project.toml`; the committed manifest resolves HTTP
  1.11.0. `listening_port` reads `server.listener.server` — exactly the kind of

*Why this is the highest-value adaptive item.* The charter's SSE/WebSocket
work (MaridLive, MaridTransport) and the Phase-8 gRPC decision (“choose an

also small in surface area — one package, one extension, one example — because
Marid deliberately hides HTTP.jl behind `TransportRequest`/`TransportResponse`.

*Elegant default (named as such, per doctrine §15):* migrate `MaridTransport`
to HTTP.jl 2.x now, and while there replace `listening_port` with a
supported way of learning the bound port (or return it from `serve_http`).
*Departure I would name if you prefer it:* pin `HTTP = "1.11"` exactly, freeze
the transport, and revisit when SSE/WS work starts — cheaper today, but it
guarantees a second migration later and blocks Phase 8.

== Perfective findings — improvements worth making

* *P01 Router allocation.* `add_route` deep-copies the whole method trie per
  insert (`_clone_trie`, `router.jl:53`) and `_insert_segments!` clones the param
  subtree a second time (:72–80), so `bind_service!` over n routes is O(n²) in
  copies. Build into a private trie and freeze once; then measure (the module
  docstring's “zero locks / immutable snapshot” claim is architectural — the
  allocation story is unmeasured).
* *P02 Middleware.* `apply_middleware` rebuilds the closure chain per request
  (`app.jl:28`). Freeze it when the app's middleware list is final, or cache per
  route generation.
* *P03 Cancellation.* `Stream` checks the context only on entry; a producer
  blocked in `put!` on a full bounded channel cannot be cancelled, and
  `Base.Event` is not a task-cancellation primitive (no propagation to blocked
  `take!`). Document the limit and consider `schedule(task, InterruptException())`
  or a token the sinks poll.
* *P04 Negotiation.* `application/json; charset=utf-8` is treated as unusable
  (`negotiate_content_type` marks any pre-`q` parameter as unusable), returning
  406 where RFC 9110 says unknown parameters should be ignored for matching.
  Also: `Vary` lists only `Accept`; if `Content-Type`-based negotiation ever
  grows, that needs revisiting.
* *P05 Codec surface.* `MediaType` and `decode_bytes(::Type{String})` are
  exported but unexercised and semantically odd; no `Content-Encoding` support.
  Remove or document.
* *P06 gRPC helpers.* `grpc_status_code` maps unknown symbols to UNKNOWN
  silently (throw instead); `format_grpc_web_trailers` does not percent-encode
  `grpc-message` as the spec requires and accepts CRLF. Both are one-line
  hardening plus tests.
* *P07 OR-Set semantics.* Liveness is decided by comparing add/remove
  timestamps (`MaridCRDT.jl:117–124`), not by observed-tag removal, so clock skew
  can resurrect a removed element; tombstones grow without bound. Either
  implement OR-Set properly (tag sets, remove preconditions) or rename the type
  and document the clock assumption.
* *P08 CRDT evidence.* The suite is examples, not properties: no
  convergence-under-random-merge-orders, no associativity/commutativity/
  idempotence over generated states. Charter Phase 6 asks for property tests;
  `Supposition.jl` or hand-rolled generators are both cheap.
* *P09 Control race test.* `MaridControl/test/runtests.jl` uses `@async` readers
  with no yield points inside the read loop, on a single thread, so it cannot
  observe a torn snapshot. Use `Threads.@spawn` and run the suite with
  `julia -t 4` in CI to make the claim real.
* *P10 Benchmarks.* `benches/marid_bench.sh` prints numbers with no baseline and
  no threshold, so “performance regression detection” (`just bench` description)
  is not what it does. No p50/p95/p99, allocation counts, slow-consumer or
  cancellation measurements — all required by brief §8.
* *P11 Problem details.* Stable `type` URIs, a `title` mapping, `Retry-After`
  for 503/504, and a `trace_id` extension member would make the errors useful to
  the browser client, which already has typed subclasses keyed on status.
* *P12 Documentation substrate.* Three copies of the project's status now exist
  (`README.adoc`, `docs/wikis/*.md`, `docs/audits/evidence-ledger.adoc`) plus a
  stale `docs/audits/README.adoc` (“no audit documents exist yet”, above ten of
  them) and the arrival pack. Pick the ledger as the single source and make the
  rest link to it.
* *P13 Test naming.* “MaridArango Full Integration Suite”, “MaridCore Complete
  Suite”, “Relationship Explorer Integration Suite” are unit tests over
  in-memory fakes. Rename to `*_unit`, or annotate the testset with an explicit
  “no external process is contacted” note — the AFFIRMATION doctrine makes this
  a correctness issue, not a style one.
* *P14 Storage aliasing.* `get_entity`/`query_entities` return the internal
  dictionaries by reference and `put_entity!` shallow-copies; a caller can
  corrupt the store. Copy on the way out (or document the aliasing).
* *P15 Live helper validation.* `turbo_stream` accepts any `action` string and
  interpolates it into an attribute; `format_sse_event` does not reject CR/LF in
  `data` (it splits on `\n` only, so a `\r` survives into the frame). Validate
  actions against the known set, reject CR.
* *P16 Repository map scope.* `docs/architecture/REPOSITORY-MAP.adoc` is
  generated from root entries plus the allowlist's annotations; it lists no
  second-level directories outside the template's own declared set, so
  `docs/audits/` (ten documents) does not appear and adding a file to it cannot
  make the map stale. `README.adoc` calls it “the authoritative map … what every
  directory is for”, which it is not yet. Either widen the generator to one
  level of `docs/`, `packages/`, `web/` and `examples/`, or soften the claim.
* *P17 Maintenance axis is empty.* `docs/governance/maintenance/{corrective,adaptive,perfective}/`
  exist as one-line stubs with no recorded findings, which is why this report
  carries its own C/A/P numbering. When these findings become issues, file them
  under that axis so the estate has one place to read the maintenance backlog.

== Recommended sequence

Ordered by “truth gained per unit of risk”, with the elegant default named.
Findings are grouped on the estate's maintenance axis (corrective C, adaptive A,
perfective P); `docs/governance/maintenance/` holds the same three directory
names but no recorded findings yet (P17).

. **Make the repository tell the truth** (C01 ✅ done here, C02, A03's stub
   recipes). No behaviour changes; deletes the three lies an agent or reviewer
   meets first. Highest value for a maintenance phase, lowest risk.
. **Fix the CI signal** (C18 + A06 + A08): regenerate `actions.lock` with the
   current tool *and* bump the standards pin in one change, then confirm the six
   workflows go green; add Julia and Bun to Dependabot so the next drift is a
   PR rather than a silent red check.
. **Decide the transport future** (A01, A02): HTTP.jl 2.x migration as one
   scoped task (transport + extension + example + `listening_port`), with the
   Julia matrix moving to LTS+current. This is the gate for SSE/WS/HTTP-2 and
   for Phase 8's gRPC decision.
. **Fix the surfaces that lie to callers** (C06, C07, C08, C09), each with a
   negative test that would have caught it: redacted RPC errors, escaped
   OpenAPI JSON with path merging, a GraphQL schema that validates, escaped
   live-helper JSON/attributes. All are pure functions and can be tested without
   a network.
. **Make storage honest** (C04, C05), then real: remove the “Arango client”
   claim or implement it; make the fallback loud; only then the container tests.
   Per the plan, this is E, and it is not release-acceptable until a real
   ArangoDB round-trips.
. **The reference application** (C15): one descriptor, `bind_service!`, unary
   JSON, `errormonitor`, no placeholder payloads. This is the smallest thing
   that makes the framework demonstrable end-to-end.
. **Then, and only then, the optional phases** (C03, C11, C13, P07–P09): control
   plane, CRDT properties, Raft. C13's truncation rule means `MaridRaft` should
   not be wired into anything until it is rewritten or removed.
. **Housekeeping** (C14, C16, C17, C19, C20, C21, C22, C23, P01–P15) as
   issue-sized tasks.

Where I depart from the obvious: a reviewer might expect “migrate to HTTP.jl
2.x” to be a pure dependency bump and put it last. I would put it third, because
it is the cheapest enabler of three charter features and because the alternative
(freeze on 1.11) guarantees a second, larger migration later. If you prefer to
defer it, the *named* departure is “pin HTTP 1.11 exactly and freeze the
transport until SSE work begins” — that is a defensible choice, but say so in
