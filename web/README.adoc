= web — browser client

Framework-independent browser client written in AffineScript
(JaffaScript face, `.affine` sources compiled to typed WebAssembly),
with thin framework integrations (`PROJECT_BRIEF.md` §5;
`docs/MARID-FRAMEWORK.adoc` frontend story).

Runtime and package manager: Bun. TypeScript is ejected for new
application code estate-wide — AffineScript is the language. Plain
JavaScript appears only in narrow interop facades where the React/Vue
ecosystem requires it.

[cols="1,3"]
|===
| Directory | Package and purpose

| `client/` | `@metadatastician/marid-client` — framework-independent client: cancellation,
errors, live subscriptions, reconnect/resynchronization.
| `react/` | `@metadatastician/marid-react` — thin React integration and lifecycle cleanup.
| `vue/` | `@metadatastician/marid-vue` — thin Vue integration and lifecycle cleanup.
| `elements/` | `@metadatastician/marid-elements` — small portable Web Components
demonstrator; not a new comprehensive widget library.
|===

The client exposes promises, `AbortSignal`, async iterables where useful,
and snapshot/subscription interfaces for reactive state. Existing GraphQL
and generated API clients must also work directly — nothing forces every
client through a universal Marid SDK.

Status: Gate 0 skeleton. Toolchain versions (Bun,
`@hyperpolymath/affinescript`) are pinned at Gate 2; packages are
implemented at Gate 4 against the browser-event contract written at
Gate 2.
